# مصفوفة اختبارات جاهزية الإنتاج — Android / iOS لـ `cranpose-video`

> **حالة المستند:** خطة اختبار على **جهاز فعلي (PENDING DEVICE RUN)**. لم يُجرَ أي تشغيل على جهاز Android أو iOS في هذه الشجرة؛ كل ما أدناه **اختبارات مقترحة** لا نتائج. البناء المحلي لـ Android كان محجوباً بغياب NDK، وقياسات Windows في `docs/final-report-ar.md` لا تُعدّ بديلاً عن هذه المصفوفة.
>
> **لا أرقام مقيسة مختلقة:** خانات «المتوقع» و«التأكيد القابل للرصد» نوعية أو تستند إلى ثوابت موجودة في المصدر (مثل `MAX_UNUSABLE_SAMPLES = 8` في `apple.rs:52`)؛ لا تُكتب قيم زمنية أو إحصائية لم تُقَس على جهاز. أي رقم يُقاس لاحقاً يُضاف بعد تشغيل فعلي مع وسم `[MEASURED]`.
>
> **الوسوم:** `[SOURCE-VERIFIED]` = قرأنا السطر مباشرة من المصدر المذكور؛ `[HYPOTHESIS]` = أثر وقت تشغيل متوقع لم يُقَس؛ `[KNOWN GAP]` = سلوك حالي معروف في المصدر ولا يطابق السلوك المطلوب للإنتاج (يُذكر في «المتوقع» حتى تبقى المصفوفة صادقة).

## 2. كيف تُقرأ المصفوفة

- **المتوقع (expected):** السلوك الصحيح المطلوب للإنتاج — ليس بالضرورة السلوك الحالي. حيث يوجد خلل معروف يُكتب صراحةً بوسم `[KNOWN GAP]`.
- **التأكيد القابل للرصد (observable assertion):** ما يُلاحَظ فعلياً على الجهاز (سجلّات، `dumpsys`، `AVAudioSession`، عدّاد إطارات، سلوك واجهة). صيغته «يحدث / لا يحدث» لا «أقل من قيمة» إلا إذا كانت القيمة ثابتاً في المصدر.
- **المنصة (platform):** `iOS`، `Android`، أو `both`.
- **العتاد المطلوب (hardware):** ما لا يمكن الاستعاضة عنه بمحاكي.
- **CI بمُفكّك وهمي (mock decoder):** `نعم` = منطق خالص قابل لاختبار وحدة؛ `جزئي` = يُختبر المنطق فقط لا مسار النظام؛ `لا` = يتطلب AVAudioSession / MediaCodec / حرارة / ذاكرة جهاز حقيقية.

أدوات الرصد المقترحة (لا تُعدّ نتائج):

```
iOS:      Xcode Instruments (CPU / Memory / Energy) + os_log
Android:  adb logcat | grep -E "cranpose|MediaCodec|AudioTrack|AAudio|BufferInfo|the decoder"
          adb shell dumpsys meminfo <pkg>
          adb shell dumpsys audio
```

## 4. إرشادات التسجيل (reporting)

لكل صف فاشل سجّل: **ID**، نوع الجهاز ونظام التشغيل، مادة الاختبار (ملف/URL)، ولقطة من `logcat`/`os_log` قبل الفشل بوقت قريب، وأي أثر في `dumpsys meminfo`/`audio` أو Instruments. لا تُستبدل هذه الملاحظات بقياسات Windows، ولا تُملأ الخانات بقيم تقديرية؛ ما يُقاس على الجهاز يُضاف لاحقاً بوسم `[MEASURED]` مع ذكر الأداة والجهاز.

**First gate for production:** `F-AUDIO` (لا كشف مسار على الجوال) و`F-CLOSE` (تحرير مشروط بإرفاق JVM) و`F-RECOVER` (تعافٍ بلا إعادة بناء على Android) هي أخطر ثلاث نقاط؛ يُنصح بتشغيل صفوف `RC-01`، `RL-02`، `SW-04` قبل بقية المصفوفة.
